# EbookForge Web v0.8.2 — iPhoneだけで、本・PDF・漫画を XTEINK X3 用 XTC/XTCH に変換（開発版）

ファイルは端末内で処理し、独自のサーバーへは送りません（例外：カクヨム取り込みは、あなた専用の中継サーバーを経由します）。

## 現在の状態（v0.8.2）

### できること
| 入力 | 出力・機能 |
|---|---|
| TXT・Markdown・EPUB・貼り付けた本文 | 縦書き／横書きの XTC。章（目次）・ルビ・傍点・縦中横・書体（明朝／ゴシック）・文字サイズ・余白・行間 |
| カクヨム・なろうの記法 | ｜漢字《かんじ》・漢字《かんじ》・《《傍点》》。画面からコピーした「漢字（かな）」のルビ（任意） |
| 小説家になろう | 話のページのコピー＆貼り付け（話の区切り・作品名・作者名を自動整理）、公式の縦書きPDF（話ごとの章・ルビを復元、長編は自動で分冊）。**本文の自動取得はしない**（利用規約 第14条23項） |
| カクヨム | 作品URLから全話を取り込み（あなた専用の中継サーバーが必要。`kakuyomu-setup.html`） |
| PDF（一般） | ①画像として（レイアウトそのまま・分割表示）②文字を組み直す（図・写真・表・罫線文字の図・AAは画像で挿入）。図が入らないときの診断 |
| 画像・ZIP/CBZ・RAR/CBR | 漫画の見開き分割・右開き／左開き・縦長画像の分割・XTC／XTCH・分冊 |

### できないこと
- OCR（文字のない画像・スキャンPDFは「文字を組み直す」不可。画像として変換は可）
- パスワード付き・DRM付きPDF、暗号化・分割RAR、HEIC/HEIF画像
- X3へのWi-Fi直接送信（保存したファイルを手動で転送）
- 小説家になろうの本文の自動取得（規約で禁止）。カクヨムの取得は中継サーバー経由のみ

## GitHub Pagesを更新する（iPhone）

1. 配布ZIPをiPhoneの「ファイル」に保存し、タップして展開します。
2. https://github.com/boufuuuuuu/ebookforge-web/upload/main を開きます。
3. リポジトリ直下にZIP **の中のファイル**をアップロードし、既存ファイルを更新します。
   - 必須：`index.html`、`app.js`、`epub.js`、`book.js`、`studio.js`、`catalog.js`、`manga.js`、`manga-ui.js`、`document-input.js`、**`kakuyomu.js`**、**`kakuyomu-setup.html`**、**`worker/kakuyomu-relay.js`**（作り方ページがここからコードを読む）、`manifest.webmanifest`
   - 推奨：`README.md`、`THIRD_PARTY_NOTICES.md`
   - `tests/`・`package.json` は公開する必要がありません（開発用）。
4. **Commit changes** を押します。
5. https://boufuuuuuu.github.io/ebookforge-web/ を開き、画面下の「読み込まれている処理プログラム」で版を確認します。古い版のときは再読み込みしてください。

## 動作の前提

### 初回のネット接続について

**PDF.jsとRAR展開エンジンは該当形式を初めて開く時にCDNから読み込みます。** GitHub PagesのJavaScriptと書籍内容を独自のサーバーに送信する処理はありません。ただし、外部配信のライブラリを実行するため、CDNの信頼・可用性に依存します。オフラインでPDF/RARを変換することは保証できません。CDNがブロックされると変換は失敗します。

- PDF.js 3.11.174 (`pdf.min.js` と `pdf.worker.min.js`, Apache-2.0): https://cdnjs.com/libraries/pdf.js/3.11.174
- node-unrar-js 2.0.2 (`esm/index.esm.js`、`unrar.wasm`, MIT + underlying UnRAR terms): https://github.com/YuJianrong/node-unrar.js
- CDN依存ライブラリ本体をZIPへ同梱してはいません。

## 制限の数値

- PDF：一般のPDFは最大35MB・120ページ（画像として）／360ページ（文字を組み直す）。なろう公式の縦書きPDFは最大70MB・8000ページ
- RAR/CBR：最大40MB、展開後125MB・180画像。ZIP/CBZ：最大70MB
- 小説の組版：1回の生成は最大900ページ（長編は分冊）
- X3の1ページ表示に必要な連続メモリ：XTC 52,272バイト、XTCH 104,544バイト

## v0.8.0（なろう公式の縦書きPDFを章・ルビ付きで組み直し）
- 「③ 本を読み込む」で、なろう公式の縦書きPDF（ヒナプロジェクト製。PDFの作成者情報で判定）を選ぶと、話ごとの章・ルビ付きの本に戻して縦書きで組み直す。それ以外のPDFは「⑤」へ案内
- 読み取り：本文・話タイトル（別の書体）・ルビ（本文の半分の大きさ）を書体と大きさで見分け、列の位置から改行・空行・字下げを、列が下端まで埋まっているかで次の列・次のページへの続きを復元。ページ番号・表紙・発行情報は除く。話タイトルは本文の頭にも出す
- ルビ：ルビと3割以上重なる字のうち、かっこ・句読点で区切られた並びで漢字が最も多いものに付ける（実物で5か所中4か所が元どおり。作り手側で位置がずれていた1か所は一部の漢字に付く）
- PDF.jsが補う半角スペース：1文字の英数字にはさまれたもの（字間）は消し、それ以外は全角スペースにする
- 分冊：X3で約800ページを超える作品は、章の切れ目で約600ページずつの巻に分け、巻を選ぶとその巻の章とタイトル（〇〇 第N巻）を自動設定
- 実物（2227ページ・98話）で確認：読み込み約7秒（PC）、第1巻571ページを約8秒で生成、CrossPointの読み込み処理で全ページ検証OK

## v0.5.7 の修正（小さい文字のPDF）

- **新機能「PDFの変換方法 → 文字を組み直す」**：PDFの文字情報を取り出し、選んだ文字サイズ（18〜30px）で組み直します。6pt以下のような小さい文字の資料でも普通の本の大きさで読めます。
  - 見出しは文字の大きさで判定（大見出し＝章・目次、中見出し＝本文中の「●」行）。見出し直前の小さいラベル（「はじめに」等）は見出しの下へ移動。
  - PDF上の折り返しで切れた行は、段落として連結します（同じ書き出し位置で右端まで届いた行を「折り返し」と判定）。
  - 縦書きのPDFは縦書きで組み直します。
  - 表・図・段組の配置は再現しません（文字だけ）。スキャン画像のPDFは文字情報がないためエラーで止まります。
- **画像として変換する場合の文字判定を2倍解像度に**：PDFを出力の2倍の大きさで描いてから文字を判定し、2×2画素ずつまとめます。1倍では途切れていた6pt前後の灰色文字の線がつながります（写真・漫画のページは従来どおり）。
- **book.js の不具合修正**：横書きで組むと1ページ目が必ず空白になっていました（文字色が白のまま描いていた）。テキスト→XTC（横書き）にも影響していた既存の不具合です。
- 目次・書名に出ていた `%E5%88%…` 形式のファイル名を日本語に戻して表示。
- 変換完了の表示に処理系のバージョン（v0.5.7）と「文字くっきり」を適用したページ数を表示（ブラウザのキャッシュで古い版が動いていないかの確認用）。
- テスト追加：`node tests/v057.cjs`


## v0.5.6 の修正（PDFの文字が不鮮明・欠ける問題）

原因は2つでした（実PDF.js 3.11.174・Chromium で再現）。
1. **縮小で細い線が欠ける**：PDFを一度大きな画像（約1131×1600）にしてから、ブラウザの簡易縮小で528×792へ縮めていたため、細い文字の線が途切れていた。
2. **固定しきい値の白黒化で灰色文字が消える**：明るさ128を境に白黒へ分けていたため、灰色の小さい文字は大半の画素が128より明るく、点々に崩れるか消えていた。

修正：
- **PDFは最終解像度で直接描画**：解析用の画像とは別に、出力と同じ倍率でPDFのベクターから描き直し、1:1で配置します（縮小を介さない）。
- **文字くっきり（適応二値化）**：各画素を周囲の平均の明るさと比べ、周囲より暗ければ文字として黒にします。灰色の細い文字は黒く残り、薄い灰色の囲みや背景は白になります。XTCHでは文字を黒、図の濃淡は従来どおり灰色で残します。
- **文字のページだけに自動適用**：紙の白が半分以上あるページにだけ適用します。写真・漫画・グラデーションのページは従来の変換のまま（出力も従来と同じ）。「PDFの文字」で「オフ」にすると従来の変換に戻せます。
- 小さい文字（7pt前後）は528×792に1ページ丸ごとだと約6pxの高さになり、白黒化を改善しても限界があります。横書きの資料は「横書き1段：上下2分割＋横向き表示」（約1.45倍）を併用してください。
- テスト追加：`node tests/v056.cjs`


## v0.5.5 の修正（v0.5.4 の「PDFの文字を拡大」を作り直し）

v0.5.4 の分割は実測で次の問題がありました（実PDF.js 3.11.174・Chromium で計測）。
- **上下2分割（初期値）は拡大率0%**：縦長ページを横長の半分にすると、画面に収める倍率が元と同じになるため文字が大きくならない（正方形 43px → 40〜43px）。さらに中央で機械的に切るため、行が上下に切断される。初期値だったため、漫画PDFや縦書きPDFまで分割されていた。
- **4分割は読み順が壊れる**：左上→右上→左下→右下の順のため、1段組の文章では各行が左右2ページに分かれる。縦書き・右開きの順序も考慮されていなかった。

v0.5.5 では「行を切らずに確実に大きくなる」分割だけを残しました。
| 選択肢 | 読む順 | 拡大率（実測） |
|---|---|---|
| 1ページのまま（初期値） | — | 1.0（v0.5.3 と出力が完全一致） |
| 横書き1段：上下2分割＋横向き表示 | 上半分→下半分（端末を時計回りに90°倒して読む） | 約1.45倍 |
| 横書き2段組：4分割 | 左段上→左段下→右段上→右段下 | 約2.0倍 |
| 縦書き2段組：4分割 | 上段右→上段左→下段右→下段左 | 約2.0倍 |
- 分割位置は**行間・段間の空白に自動で吸着**（空白が無い場合は文字を切る量が最小の位置）。
- 分割したページ同士は同じ倍率・同じ位置に揃えます。
- 1段組の縦書きの本は、列を切らずに拡大する分割が原理的に存在しないため選択肢から外しました（文字を大きくしたい場合はテキスト変換やEPUBの経路を使ってください）。
- テスト追加：`node tests/v055.cjs`


## v0.5.3 の修正（日本語PDFが白紙になる問題の根本対策）

- **原因**：PDF.js に CMap（日本語の文字コード表）の場所を渡していなかったため、フォントを埋め込んでいない日本語PDF（UniJIS-UCS2-H 等）は**文字の描画もテキスト抽出も空**になり、全ページ白紙のまま「変換完了」になっていました。Safari 固有の問題ではありません（Chromium でも同じ症状を再現）。
- **修正**：`cMapUrl`／`cMapPacked`／`standardFontDataUrl` を指定。読み込み先は jsDelivr の `pdfjs-dist@3.11.174`（PDF.js 本体と同じ版）。リポジトリ直下に `cmaps/` と `standard_fonts/` フォルダを置いた場合はそちらを優先します（CDN 非依存にしたい場合のみ。npm の pdfjs-dist@3.11.174 から同名フォルダをコピー）。
- **v0.5.2 の文字再描画フォールバックを縦書きでは使わない**：縦書きを `fillText` で描くと全行が1行に重なって潰れ、しかも「インクあり」と判定されて壊れたページが保存されていました。縦書きの場合は保存せずエラーにします（横書きの救済は維持）。
- **白紙ガード**：描画を始めてから最初の3ページが連続して白紙なら、描画失敗として中止します（白紙のXTCを黙って保存しない）。本の途中にある白紙ページは従来どおり通します。
- 検証（実PDF.js 3.11.174・Chromium）：フォント非埋め込みの縦書き日本語PDF 8ページ → v0.5.2 は全ページ黒画素0、v0.5.3 は全ページ描画。CDN に届かない場合は3ページ目でエラー停止。埋め込みフォントPDF・画像PDFは従来どおり変換。iPhone Safari・X3 実機は未検証。


## v0.5.2 の修正（PDF→X3 のメモリエラー対策と品質修正）

- **縦長分割の誤作動を修正**：v0.5.0 では余白トリミング「後」の形で縦長判定していたため、章扉や数行だけの縦書きページが細長い領域と誤認され、**1文字ずつ・行の途中で上下に切断**されていました（30ページのPDFが78ページに膨張）。判定をトリミング「前」の形に変更し、PDFのページは縦長分割の対象外にしました。
- **PDFは文書単位で余白を統一**：ページごとに余白を切ると、文字の少ないページだけ極端に拡大されていました。PDFは先頭・末尾を含む最大9ページの本文範囲から共通の余白を決め、全ページ同じ倍率にします（端まで絵があるページは計算から除外）。
- **X3でのXTCHに警告**：端末は1ページ表示ごとに連続メモリを確保します（XTC＝52,272B、**XTCH＝104,544B**）。X3の解像度ではXTCHの確保量が白黒の2倍になり、メモリ不足の最有力原因になります。出力形式の下に必要メモリを表示し、XTC（白黒）＋順序ディザを推奨にしました。
- **分冊して保存**：50／100／150ページごとに分けて保存できます。各巻の目次は付け直し、巻頭には直前の章を引き継ぎます。iPhone Safariの連続ダウンロード制限を避けるため、巻ごとに保存ボタンを表示します。
- テスト追加：`node tests/v051.cjs`
- 検証：実際のPDF.js 3.11.174を使ったChromium上のPDF→XTC/XTCH変換、CrossPoint最新版のヘッダ定義でビルドした検証器による全ページ照合、MD5一致を確認。iPhone SafariとX3実機は未検証。
